# S2M 仿真演示视频

这个文件夹用来把实验过程录成视频给别人看。每个视频都是 AI2-THOR 仿真里的一个 EB-Navigation 回合，画面同时展示智能体看到了什么、小模型回答了什么、控制器做了什么决定。

## 三种模式

| 模式 | 需要模型服务器 | 用途 |
|---|---|---|
| **实时画面（show）** | 自动启动 | 浏览器里实时看 S2M 调用本地小模型跑回合，可以当场选回合、开始、停止，每次自动录像 |
| **回放（replay）** | 不需要，几秒出一个视频 | 重演论文测试集里已保存的回合，内容和论文数字一一对应 |
| **实时录像（live）** | 需要，先 `serve` | 命令行跑一个回合并录像，不开浏览器 |

## 实时画面（推荐用来现场演示）

```bash
bash demo/run_demo.sh show      # 没有模型服务器时先启动它（约 1 分钟），然后自动打开 http://127.0.0.1:8765
```

页面左边是实时画面（第一视角、俯视地图、模型的回答和控制器的决策），每走一步刷新一次。右边可以选数据集（测试集 / 开发集）、子集和回合；测试集的回合旁边标着论文记录里 S2M 和 EB prompt 各自成功（✓）还是失败（✕），方便挑例子。"每步额外停顿"默认 1 秒，让观众跟得上。下方实时列出发给小模型的每一个问题、它的回答和耗时，例如"画面里有「pot」吗？ → P(是) = 0.93"。每次运行都录成 `demo/videos/live_<时间>_<数据集>_<子集>_ep<编号>_zh.mp4`，页面底部可以直接点开。

- 想让同一局域网里的其他人用自己的电脑观看：`DEMO_ARGS="--host 0.0.0.0" bash demo/run_demo.sh show`，别人打开 `http://<这台机器的IP>:8765`。注意，能打开页面的人也能点"开始运行"，只在可信的网络里这样用。
- 画面文字改英文：`DEMO_ARGS="--lang en" bash demo/run_demo.sh show`。
- 结束时在终端按 Ctrl+C，再运行 `bash demo/run_demo.sh stop` 关掉模型服务器。
- 一次只能跑一个回合，运行中再点"开始"会提示已有回合在运行。

回放的做法是在模拟器里重置同一个回合，再依次执行记录里的动作，每一步都核对位姿是否与记录一致（程序会打印不一致的步数，正常应为 0）。模型的回答和控制器的决策取自保存的记录，S2M 的占据地图则用重演得到的深度图重新构建，构建方式和智能体运行时完全相同。

实时运行和保存的记录可能有细微差别，因为 GPU 批量推理不是逐位确定的。论文里的数字以保存的记录为准。

## 快速开始

在仓库根目录 `~/robotics-agent` 下运行：

```bash
# 论文图 2 的三个回合，每个都是 EB prompt 与 S2M 左右对比（约 10 秒全部完成）
bash demo/run_demo.sh gallery

# 回放任意一个测试回合：子集  回合编号  智能体(both | s2m | eb)
bash demo/run_demo.sh replay long_horizon 14 both
bash demo/run_demo.sh replay visual_appearance 3 s2m

# 实时运行：先启动模型服务器（约 1 分钟），再跑一个回合，最后关掉
bash demo/run_demo.sh serve
bash demo/run_demo.sh live base 19          # 默认用测试集；最后一个参数写 dev 则用开发集
bash demo/run_demo.sh stop
```

视频保存在 `demo/videos/`，文件名里带子集、回合编号、智能体、模型和语言。

额外参数通过 `DEMO_ARGS` 传入，例如：

```bash
DEMO_ARGS="--lang en --hold 1.2" bash demo/run_demo.sh replay base 19 both
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `--lang zh / en` | 画面文字语言 | `zh` |
| `--hold 秒数` | 每一步在视频里停留多久 | `0.8` |
| `--fps` | 视频帧率 | `10` |
| `--model qwen3 / qwen25` | 回放哪个模型的记录（实时模式要与 `serve` 的模型一致） | `qwen3` |
| `--no-target` | 不画真实目标的星号（仅回放） | 画 |
| `--out 路径` | 指定输出文件 | 自动命名 |

五个子集名：`base`、`common_sense`、`complex_instruction`、`visual_appearance`、`long_horizon`，每个子集有 60 个回合（编号 1–60）。

## 实时观看

本机的 OpenCV 不带窗口支持，所以实时模式每走一步会把当前画面写到 `demo/videos/preview.png`。在 VS Code 里打开这个文件，它会随着回合进行自动刷新。终端里也会逐步打印动作、行为模式和距目标的距离。

## 画面怎么看

```
┌ 顶栏：智能体名称、模型、任务指令、当前步数 ───────────────────────────┐
│ 第一视角（RGB）        │ 俯视地图               │ 右侧文字栏             │
│ S2M：模型给出的目标框   │ 浅灰：可到达的地面      │ 上：小模型回答的两个问题 │
│ 碰撞时底部出现提示       │ 浅蓝/深灰：S2M 已观测的 │    （目标可见吗？在哪？）│
│ 结束时显示成功/失败      │ 空地/障碍；圆点：目标假设 │ 下：控制器的决策         │
│                        │ （越大证据越多）；空心：已排除 │ （行为、目标点、下一动作）│
│                        │ 虚线圈：当前目标点；扇形：视野 │                    │
│                        │ 星号：真实目标（仅供观众）   │                    │
└ 底部：每一步一个格子（彩色=执行成功，灰色✕=被拒绝），以及图例 ──────────┘
```

- 蓝色是 S2M，橙色是 EB prompt（基准自带的接口，同一个小模型直接输出 JSON 计划）。
- EB prompt 的俯视图只是给观众看位置用的：这个智能体本身不维护地图，右侧显示的是它输出的视觉描述、推理和计划。
- 对比视频是 2560×720，两个画面左右并排。如果要放进 16:9 的幻灯片，可以只录单个智能体（1280×720），或者把对比视频按宽度缩放。

## 推荐展示的回合

| 命令 | 展示什么 |
|---|---|
| `replay long_horizon 14 both` | 目标在身后：EB prompt 20 步都没看到目标；S2M 先环视，转两次就找到了，11 步成功 |
| `replay base 19 both` | 障碍挡路：EB prompt 20 次移动全被拒绝，原地不动；S2M 撞一次后绕开，18 步成功 |
| `replay visual_appearance 28 both` | S2M 的失败案例：只靠外观描述时，小模型没能把目标框出来，这正是论文写到的剩余差距 |

想找更多例子，可以对比 `runs/eb_nav/test/` 下两个智能体的记录，挑 EB prompt 失败而 S2M 成功的回合。

## 依赖与注意事项

- 用的是 `embnav_thor` 环境（AI2-THOR + OpenCV + Pillow）。视频编码用 `imageio-ffmpeg` 自带的 ffmpeg 输出 H.264，浏览器、PowerPoint、微信都能直接播放；没有它时会退回 OpenCV 的 MPEG-4 编码。
- 中文用系统里的 Noto Sans CJK 字体。
- 这台机器的 GPU 只有 8 GB，桌面也在用。实时模式会启动模型服务器（约 4.6 GB 内存）和模拟器；所有进程都设置了 `oom_score_adj=1000`，内存不够时系统会先结束实验进程，不会先结束桌面程序。用完请 `bash demo/run_demo.sh stop`。
- 不要在跑实验队列的同时开实时模式，两者会争用 GPU 和 8000 端口。
