The estimated-depth configuration uses the DEV calibration stored in
\texttt{data/depth\_calib.json}: AbsRel $=0.1321$, scale $=0.37743$, 60 calibration frames.  This is a
calibration artifact, not an independent TEST result.  The S2M records log mean VLM calls per episode of

records log Qwen3 means of 8.21 calls, 28,766 prompt tokens and 2,425 completion tokens, and Qwen2.5 means of
12.10 calls, 43,469 prompt tokens and 12,280 completion tokens.  These are not a matched cost comparison.

\paragraph{Grounding probe.} The raw JSONL files in \texttt{runs/grounding/} provide an auxiliary start-view
recognition check, not a navigation metric.  Using saved ground-truth boxes only for evaluation and IoU $\geq0.3$,
Qwen3 test hit/visible rates are 78.7, 69.3, 77.3, and 49.3\% on Base, Common, Complex, and Visual (75 visible
instances each); Qwen2.5 rates are 40.0, 33.3, 37.3, and 18.7\%.  The corresponding files also retain false-box
and lift-error fields.  Candidate-verification JSONL has no checked aggregate in this paper and remains a handoff
artifact rather than a numerical claim.

\subsection{Audit Boundaries}
\label{app:audit-boundaries}
The oracle geometric planner explicitly requests \texttt{oracle\_target}; this privileged input makes its 91.3\%
TEST score an upper-bound diagnostic only.  In contrast, S2M receives RGB, simulator depth, and exact pose,
whereas the EB-prompt adapter forwards RGB alone.  The vLLM context settings (Qwen3: EB 8192, S2M 2048;
Qwen2.5: EB 10240, S2M 2048) are maxima, not observations of actual token use.  Finally, the Qwen2.5 EB-prompt
summary contains 768 JSON decode fallbacks across 255 affected episodes; its score should not be interpreted as a
clean planning comparison.  Full paths, raw-file coverage, and audit evidence are maintained in
\texttt{docs/experiment\_inventory.md}.
