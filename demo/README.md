# S2M 仿真演示

这个文件夹用来把实验过程展示给别人看：同一个 4B 小模型（Qwen3-VL-4B，4-bit，本地运行）用两种方式控制 AI2-THOR 里的智能体，左右并排对比。

- **左：EB prompt**。基准自带的用法：模型看图后直接输出一整段 JSON 多步动作计划。
- **右：S2M（本文方法）**。模型只回答“目标在不在画面里、在哪里”，几何控制器负责建图、记忆和规划动作。

## 两种用法

| 命令 | 需要模型服务器 | 用途 |
|---|---|---|
| `bash demo/run_demo.sh show` | 自动启动 | **现场演示**：浏览器里实时看两个智能体同时调用模型、同时运行，每次运行自动录成并排视频 |
| `bash demo/run_demo.sh replay 子集 编号` | 不需要 | 重演论文测试集里已保存的回合，生成并排视频，内容与论文数字一一对应 |

```bash
bash demo/run_demo.sh show                      # 约 1 分钟后浏览器打开 http://127.0.0.1:8765
bash demo/run_demo.sh replay long_horizon 14    # 约 25 秒，输出 demo/videos/compare_long_horizon_ep14_qwen3_zh.mp4
bash demo/run_demo.sh gallery                   # 论文图 2 的三个回合
bash demo/run_demo.sh stop                      # 用完关闭（实时页面在终端按 Ctrl+C 也会退出）
```

画面文字改英文：在命令前加 `DEMO_ARGS="--lang en"`。

## 实时演示页面

- 上方是两个智能体的实时画面，左 EB prompt、右 S2M。两者同时开始、各自按自己的速度运行。
- 智能体每走一步，摄像机都平滑移动过去（每次前进 0.6 秒、转身 0.9 秒，15 帧/秒），不再是一下跳过去。
- 等模型回答时，画面下方会出现“正在问模型 · 2.3 s”和正在问的问题。EB prompt 每次要生成一整段计划，所以思考时间明显更长；这本身就是对比的一部分。
- 下方左侧选择数据集、子集、回合并开始或停止。回合列表里标着论文记录中两边各自成功（✓）还是失败（×），方便挑例子。“每次决策后停顿”默认 0.6 秒。
- 下方两栏实时列出每个智能体发给模型的每一个问题、回答和耗时。
- 每次运行都录成 1920×1080 的并排视频 `demo/videos/live_<时间>_<数据集>_<子集>_ep<编号>_zh.mp4`，按真实时间录制，页面上可以直接点开。
- 想让同一局域网的其他人观看：`DEMO_ARGS="--host 0.0.0.0" bash demo/run_demo.sh show`，别人打开 `http://<这台机器的IP>:8765`。能打开页面的人也能点“开始运行”，只在可信网络里这样用。
- 不开浏览器、直接录一个回合：`~/miniforge3/envs/embnav_thor/bin/python demo/live_view.py --once test:long_horizon:14`。

## 画面怎么看

每个智能体一栏，从上到下：

- 名称和步数（上限 20 步）。
- 左：智能体看到的画面。S2M 的画面上会画出模型给的目标框；撞到障碍时底部提示；结束时显示成功或失败及距目标的距离。
- 右：俯视地图。浅灰是可到达的地面。S2M 一栏里，浅蓝和深灰是它自己观测到的空地和障碍，蓝点是目标假设（越大证据越多，空心带斜线是已排除的），黑圈是当前目标点，扇形是视野。EB prompt 不维护地图，它这一栏的俯视图只是给观众看位置用的。星号是真实目标，只给观众看，两个智能体都看不到。
- 一排格子：每一步一个，彩色是执行成功，灰色 × 是被模拟器拒绝。
- 文字：S2M 栏是模型回答的问题和几何控制器的决策；EB prompt 栏是模型输出的画面描述、推理、计划和执行进度。

## 回放和实时的区别

- **回放**在模拟器里重置同一个回合，依次执行保存记录里的动作，并核对每一步的位姿与记录一致（终端会打印不一致的步数，正常为 0）。模型回答和决策取自记录。回放不重现思考时间，每次决策固定停顿 `--pause` 秒（默认 1 秒）。
- **实时**真的调用模型。和保存的记录相比可能有细微差别，因为 GPU 批量推理不是逐位确定的；论文数字以保存的记录为准。

## 技术说明与注意事项

- 智能体和规划器看到的始终是基准原本的相机画面。平滑动画来自另一台与它位置、朝向、视野完全相同的“显示相机”，只用于展示，从不交给模型。
- 实时演示需要模型服务器的上下文至少 4608 token（EB prompt 每次请求最多约 3.9k token），`show` 会以 5120 token、76% 显存启动它，在 8 GB 显卡上能和两个模拟器同时运行。如果已有一个 2048 token 的旧服务器在跑，`show` 会提示先 `stop`。
- 视频用 `imageio-ffmpeg` 自带的 ffmpeg 编码为 H.264，浏览器、PowerPoint、微信都能直接播放。中文用系统的 Noto Sans CJK 字体。
- 所有进程都设置了 `oom_score_adj=1000`：内存不够时系统先结束演示进程，不先结束桌面程序。
- 不要在跑实验队列的同时开实时演示，两者会争用 GPU 和 8000 端口。
- 文件：`render.py` 画面布局；`sim.py` 模拟器、显示相机、平滑动画和回合驱动；`agents.py` 两个智能体的实时版和回放版；`live_view.py` 实时页面；`replay.py` 回放视频；`run_demo.sh` 入口。
