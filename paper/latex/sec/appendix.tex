\noindent\textbf{Candidate recall.}
For each episode of \ours we ask whether any logged detection or fused hypothesis ever lies within $R$ of the true
target in the floor plane. The perception log covers every step, and hypotheses are stored in the simulator frame,
so only exact-pose runs are evaluated (\cref{tab:app-recall}). Changing $R$ from 0.5 to 1.0\,m changes no subset by
more than 3.3\,pp. Some successes have no such candidate (4--5 per Qwen3 run) because EB-Navigation ends an
episode as soon as the agent is within 1\,m, including during exploration.

\noindent\textbf{Single-view probe.}
The probe of \cref{sec:diagnosis} renders each test start view and the three other 90$^\circ$ headings; a box is a
hit at IoU${\ge}0.3$ with the simulator's instance box. Base queries the category name; the other subsets use the
phrase that \ours extracts from the instruction. A second probe asks for every candidate box in the views where the
target is visible (70 per subset for Common, Complex, and Visual). The target is among the candidates in 73, 80, and
57\% of these views, but only 7 of the 210 views contain the target together with another candidate, too few to
compare ways of choosing among candidates.

\subsection{EB-Prompt Output Validity with Qwen2.5-VL-3B}
\label{app:qwen25}
The benchmark's planner parses each reply with \texttt{json.loads} and substitutes a uniformly random action on
failure. Our client reproduces the benchmark's Qwen call: JSON-schema guided decoding with the benchmark's schema,
temperature 0, and a 4{,}096-token completion budget. Of 3{,}631 Qwen2.5 planner calls, 768 (21.2\%) fail to
parse, in 255 of 300 episodes; no call fails for any other reason. Regressing each episode's completion tokens on
its numbers of parsed and failed calls gives 185 tokens per parsed call and 4{,}102 per failed call, so the failed
calls run into the budget before the JSON closes. The schema bounds neither string length nor the number of actions,
so a greedy repetition loop is never forced to end. Qwen3-VL-4B has no failures (295 completion tokens per call).
With the original schema, Qwen2.5 scores 8.3, 6.7, 6.7, 6.7, and 0.0\% on the five subsets (5.7\% overall).

\noindent\textbf{Length-bounded rerun.}
We repeated the run with the same prompt, examples, parser, server, and decoding, adding to the schema a
1{,}500-character limit on each text field, an 80-character limit on action names, and 1--20 actions. The limits
were set from the longest development-split outputs (941 characters, 8 actions) before the test run. They never
bind for Qwen3-VL-4B, whose longest test output field has 823 characters and whose longest plan has 6 actions. All
2{,}439 Qwen2.5 calls now parse (median 188 completion tokens), and success is 6.3\% (\cref{tab:main}). The loops
remain: 397 calls (16.3\%) reach a limit, 361 of them the 20-action cap and 72 a text-field limit, and in 285 of
the 361 capped plans a single action is repeated at least 15 times. Both runs measure the same behavior through different fallbacks and agree
($+0.7$\,pp; 15 versus 13 discordant episodes; $p=0.85$). We use the bounded run as the baseline because none of its
actions is random. All servers use vLLM's default sampling configuration, so the Qwen2.5-VL checkpoint's suggested
repetition penalty is not applied to either agent.

\subsection{Implementation and Evaluation Details}
\label{app:impl}
\noindent\textbf{Development split.} 150 episodes on FloorPlan1--10, 201--210, and 301--310, kitchen, living-room,
and bedroom scenes that the test set (FloorPlan11--30, 211--230, 311--330) does not use, built with the benchmark's task-generation settings (start 2.5--3.0\,m from the
target, horizon 0) and its instruction files, with the same five subsets.

\noindent\textbf{Monocular depth.} Depth Anything V2 Metric-Indoor-Small runs on the CPU. One global scale
(0.377) is fitted on 60 development frames against simulator depth (AbsRel 0.132); no test frame is used.

\noindent\textbf{Outcome categories.} A failed episode is labeled by the first matching rule: the target never
enters the view; final distance at most 1.5\,m; the target is out of view in the last five steps; at least 30\%
of actions are rejected; at least three immediate reversals; otherwise approach failure.

\noindent\textbf{Cost.} \ours issues 51.7--53.0 short single-image VLM queries per Qwen3 episode, counting crops
and tiles (98.3 with Qwen2.5). The EB prompt issues 8.2 calls per Qwen3 episode with on average
28{,}766 prompt and 2{,}425 completion tokens. The two agents are served with different context limits (2{,}048
tokens for \ours, 8{,}192 and 10{,}240 for the EB prompt with Qwen3 and Qwen2.5), so we do not compare their wall
time.

\noindent\textbf{Information access.} Neither agent receives the target position or any simulator object state.
The benchmark's per-step feedback also contains the distance to the target; \ours reads only the executed action
and its success flag from it, and the EB prompt only the action and its feedback message.
